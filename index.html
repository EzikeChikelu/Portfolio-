A closer look / Engineering notes

Behind the build.

The thinking behind the interface: the problem, the decisions, and what each project taught me.

CASE 01Make blockchain data easier to inspectStellar-Lens · Data clarity / Explorer tooling+
THE CHALLENGE

Public-ledger information can be technical and difficult to scan when all you need is a clear view of an account or transaction.

THE APPROACH

Build a focused, read-only browser experience around public Stellar data, with a clear interface and a TypeScript-based frontend.

WHAT IT SHOWS

Product thinking for developer tools: present useful information clearly while keeping the scope deliberately read-only.

Explore the implementation ↗
CASE 02Give market data a clearer homeLive Market Dashboard · Data UI / Visualization+
THE CHALLENGE

Market information changes quickly. A useful dashboard should make prices and movement easy to scan instead of burying the signal in visual noise.

THE APPROACH

Explore a compact dashboard layout with market-oriented visual hierarchy, trend charts, and space for a watchlist and API-driven data.

WHAT IT SHOWS

How interface decisions, lightweight data visualization, and refresh behavior can work together in a live-feeling product.

Explore the implementation ↗
CASE 03Turn a brand site into a better journeyFashion Design Website · UX / Responsive web+
THE CHALLENGE

A visual business site needs to do more than look good: visitors should understand the brand and know how to make an inquiry or book.

THE APPROACH

Refine the responsive presentation and give booking and inquiry interactions a more considered, guided flow.

WHAT IT SHOWS

Applying design and frontend work to a real customer journey, not just a static visual layout.
